01 / Execution hierarchy

代码的层级，
如何落到硬件上。

Grid、Block、Warp、Thread 是工作组织方式；GPU、SM、执行管线是硬件。两者通过调度建立联系，并非一一对应的物理部件。

01 / LAUNCH

Grid

一次 kernel 启动产生的全部线程块。不同 Block 通常可以独立执行，顺序不能预设。

映射 → 整个 GPU
02 / COOPERATE

Block

协作与共享内存的基本范围。一个传统 Block 驻留在一个 SM，一个 SM 可同时容纳多个 Block。

驻留 → 单个 SM
03 / SCHEDULE

Warp

连续 32 个线程组成一个 Warp。调度器选择就绪 Warp，向执行管线发射指令。

发射 → SM 的执行管线
04 / EXECUTE

Thread

每个线程拥有自己的索引与寄存器状态。CUDA Core 是算术执行单元，不与线程永久绑定。

状态 → 寄存器与执行上下文

示例：kernel<<<120, 256>>>(...) 创建 120 个 Block，每个 Block 有 8 个 Warp，共 30,720 个线程；它们会按 SM 资源分批驻留和执行。较新架构还支持 Thread Block Cluster 等扩展。

上方为调用顺序片段，省略指针声明、错误检查和 Stream 创建 / 销毁。异步传输使用已分配的 pinned 主机内存；代码中的 d_a / d_b / d_c 为设备指针。播放是逻辑示意，不代表真实硬件耗时。

CPU ↔ GPU：PCIe

独立显卡通常经 PCIe 传输，Copy Engine / DMA 搬运数据。CPU 负责提交和协调。

GPU 内：L2 ↔ 显存

SM 的全局访存通过缓存与内存控制器访问显存；缓存命中时无需读取 DRAM。

SM 内：寄存器 / Shared

寄存器保存线程状态；Shared Memory 由同 Block 线程协作管理。L1 是缓存。

重叠：需要明确条件

Pinned 内存、异步 API、独立 Stream、正确依赖和硬件能力共同决定拷贝与计算能否重叠。

NVLink 常用于受支持的 GPU 互联；Grace–Hopper 等平台可通过 NVLink-C2C 连接 CPU 与 GPU。普通 x86 + 独立显卡并不默认具备这种链路。统一内存则由运行时与硬件管理放置、迁移或远程访问，仍然存在通信成本。
