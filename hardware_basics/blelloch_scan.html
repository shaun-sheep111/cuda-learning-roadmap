Blelloch Scan（工作高效前缀和）

day19 流压缩里的 scan 用的就是 Blelloch 算法。它把数组看成一棵二叉树， 分 up-sweep（求和往上）和 down-sweep（撒前缀和往下）两趟。 看清 index=(tid+1)*stride*2-1 怎么把连续线程映射到树节点，以及为什么要跳步。

本步写入(index) 被读取(index-stride) 刚变化 树根
↑ 哪些 tid 在本步干活（橙色=活跃，灰=空转）
两个关键点
① 线程≠固定数据：8 个线程全程在，但每层用 index=(tid+1)*stride*2-1 让 连续的 tid 0,1,2… 认领本层要合并的节点；if(index<BLOCK_SIZE) 自动筛掉多余线程 → 活跃数 4→2→1，正好是树每层的节点数。
② 为什么跳步：跳步精确命中二叉树该层的节点，每个部分和只算一次，总加法 O(n)（工作高效）；若相邻叠加会重复计算、既慢又错。

对应 day19 的代码

// Up-sweep（求和树） for (int stride = 1; stride < BLOCK_SIZE; stride <<= 1) { int index = (tid + 1) * stride * 2 - 1; if (index < BLOCK_SIZE) sdata[index] += sdata[index - stride]; __syncthreads(); } // 根清零（exclusive 关键） if (tid==0){ blockSums[bid]=sdata[N-1]; sdata[N-1]=0; } // Down-sweep（撒前缀和） for (int stride = BLOCK_SIZE/2; stride > 0; stride >>= 1) { int index = (tid + 1) * stride * 2 - 1; if (index < BLOCK_SIZE) { int tmp=sdata[index-stride]; sdata[index-stride]=sdata[index]; sdata[index]+=tmp; } __syncthreads(); }
